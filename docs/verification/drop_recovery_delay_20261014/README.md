# 投递恢复两种配置（2026-10-14）

直接修改板端，默认配置一。

## 配置一：调用后等待0.5秒，不等待ACK

```yaml
drop_system:
  recover_without_ack: true
  recovery_delay_sec: 0.5
```

从异步客户端开始调用时以steady_clock计时，满0.5秒后下一20Hz控制周期进入原恢复上升流程；恢复高度和原状态/稳定条件达标后继续下一目标。调用结果提前成功、失败或RPC卡住均不改变等待时间；调用开始不代表硬件释放成功。回执仍保留，槽位按调用消耗，不自动重投。计时继续于RPC完成之后，避免快速回执导致永不恢复。

## 配置二：成功ACK后恢复

```yaml
drop_system:
  recover_without_ack: false
  recovery_delay_sec: 0.5 # 本模式不使用此参数
```

沿用原成功回执门槛：成功ACK后上升，恢复达标后继续下一目标；失败或无ACK不当作成功，不自动重投。
