# 投递水平补偿双模式与下降20秒兜底（2026-10-13）

基于 `liftrace_board_trial_20260928@008c3b23`。仅修改投递补偿入口、投递超时几何及对应许可/配置/测试；H降落、起飞、导航路线与舵机原始实现不变。

## 水平补偿模式

正式现场配置和08试飞的 `settings.yaml` 使用：

```yaml
drop_horizontal_compensation_mode: 2
drop_descent_mode: 1
drop_descent_speed_mps: 0.20
```

两个模式互不代替下降模式1/2/3，参数在节点启动时读取。

| 补偿模式 | 下降入口 |
| --- | --- |
| 1 | 飞控中心及实际投口XY误差均≤4cm、两者水平速度最大值≤0.1m/s，连续满足1秒；至少3个不同odom样本，样本间隔≤0.2秒 |
| 2（默认） | 当前有效样本中，标准四类双XY误差均<6cm；红十字均<4cm。没有速度或累计稳定时间门槛 |

不检查窗口位移。模式1任一位置/速度/有效性超限重置稳窗，重复odom不能累计新样本。模式2保留当前分支的单样本行为。下降前始终在观察高度进行槽位补偿，末段超时不能跳过冻结与补偿。

生成后对应 `drop_system/pre_descent/mode`。模式1使用 `stable_xy_tolerance_m: 0.04`、`max_horizontal_speed_mps: 0.10`、`stable_duration_sec: 1.0`；模式2使用 `xy_tolerance_m: 0.06` 与 `red_cross_xy_tolerance_m: 0.04`。两套位置容差独立。

## 下降20秒兜底

```yaml
drop_system:
  release_timeout:
    enabled: true
    after_sec: 20.0
```

从同一动作**首次成功进入下降**的控制器时间开始计算；ALIGN开始、靶心冻结、上下文续租和下降轨迹的重复更新都不重新启动这个计时。独立Z轨迹初始化失败时不启动。三种下降模式使用同一个计时规则。

未满20秒时沿正常高度/许可路径释放，条件早到可提前投递。满20秒后绕过控制器XY/高度阈值，也绕过许可节点的高度、承诺漂移及当前视觉几何等待：即使还在0.8m或偏离冻结点，仍提交同身份的投递请求。保持原下降指令直到成功回执，之后沿原上升恢复流程接续。

控制器通过现有 `/uav_vision/drop_alignment_feedback` 发布 `reason=descent_timeout_ready`。许可节点仅接受新鲜、有效、已冻结、与当前有效ALIGN上下文完全同身份且同frame的反馈，再签发 `reason=descent_timeout_release` 的短期许可。消息字段和服务结构未变，只更新消息注释；控制器和许可节点必须同步部署。无需单独让许可节点再累计20秒，也不存在等待许可才能生成超时状态的循环依赖。

取消、任务deadline、错身份/槽位、陈旧或无效反馈、飞控掉线/未解锁/退出OFFBOARD、近墙边界及动作防重复仍阻止投递。时钟回退禁用当前动作的兜底，普通正常路径仍可用。取消、完成和状态复位清空下降起点；旧反馈/旧许可不能让下一目标提前超时。仅有效严格上下文的投递启用该许可通道，旧固定航线及H任务不启用。

满20秒表示开始允许投递请求，并非硬件必须在该时刻完成。保留异步原服务、同槽只调用一次、匹配成功ACK才确认完成、失败或未知结果不自动重复。
